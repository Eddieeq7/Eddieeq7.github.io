01

What I built

Four pieces, each doing one job. A packet passes through them in this order.

STEP 1 · RECEIVE

A receiver that never falls behind

One thread waits for packets and, the moment they arrive, grabs them in batches of up to 64 so the network buffer never overflows.

epoll (edge-triggered) + recvmmsg on a non-blocking UDP socket

STEP 2 · HAND OFF

A queue with no locks

Packets go to worker threads through a queue designed so the two sides never wait on each other. Each satellite subsystem always goes to the same worker.

Lock-free single-producer/single-consumer ring buffer using C++ atomics

STEP 3 · CHECK

A corruption check

Every packet carries a checksum. If even one bit changed on the way, the worker rejects it.

Custom binary protocol with CRC-32, written byte by byte

STEP 4 · ACCOUNT

A tracker for every packet

Each packet is numbered. Gaps mean lost, repeats mean duplicate, late arrivals mean out of order, and the counts fix themselves when a "lost" packet shows up late.

Sequence numbers + a sliding-window bitmap, per subsystem

    04

    Technical details

    For engineers. Open any section.

    The packet format protocol.hpp

    Little-endian, serialized byte by byte, so it never depends on the CPU's byte order or struct padding. Decoding rejects short frames, wrong magic/version, length mismatches, oversized payloads, and CRC failures.

    Why one queue per worker, split by subsystem station.cpp

    A single-producer/single-consumer queue needs only one atomic load and one atomic store per operation, with no locks and no compare-and-swap loops. To keep every queue truly single-producer/single-consumer with several workers, the receiver routes each packet by apid % workers. A bonus: each subsystem's packet numbers belong to exactly one thread, so the tracker needs no locking at all.

    The trade-off: with three subsystems and two workers, one worker gets two-thirds of the traffic (you can watch its queue fill first in the demo). A real deployment would assign subsystems by measured traffic.

    Backpressure is counted, never hidden. If a queue is full, the receiver drops the packet and counts it instead of blocking. Blocking would stop it reading the socket, and the kernel would then drop packets silently.

    The lock-free queue, in full spsc_ring.hpp

    Head and tail live on separate cache lines (no false sharing). Each side caches the other's index and only re-reads the shared atomic when the queue looks full or empty, so most operations touch no shared memory.

    bool try_push(T&& v) noexcept {            // producer thread only
    const size_t tail = tail_.load(memory_order_relaxed);
    if (tail - head_cache_ > mask_) {
        head_cache_ = head_.load(memory_order_acquire);
        if (tail - head_cache_ > mask_) return false;   // full
    }
    slots_[tail & mask_] = std::move(v);
    tail_.store(tail + 1, memory_order_release);       // publish
    return true;
}

std::optional<T> try_pop() noexcept {              // consumer thread only
    const size_t head = head_.load(memory_order_relaxed);
    if (head == tail_cache_) {
        tail_cache_ = tail_.load(memory_order_acquire);
        if (head == tail_cache_) return std::nullopt;   // empty
    }
    T v = std::move(slots_[head & mask_]);
    head_.store(head + 1, memory_order_release);
    return v;
}
